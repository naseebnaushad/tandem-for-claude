## 1. Summary
1. **Prove the main promise** before 0.1.0: continue a chat on the other seat, in a
   desktop window and in a terminal. The design rests on it, and it hasn't been tried
   end to end yet (S-01).
2. **Test on a real Windows PC and a Linux machine.** The packages build, but the code
   that finds and starts Claude follows defaults that haven't been checked there (S-02).
3. **Remove the restart step.** New chats only appear after a Claude window restarts.
   Restarting a closed profile automatically, or a clear "Restart to see N new chats"
   button, would make sync feel instant (S-03).

## 3. Details
### S-01 Run the cross-seat resume tests
**Problem.** Test Cases SYNC-M04 and PROF-M07 aren't run. So far only "the chat is listed
and its history loads" has been checked (SYNC-M01).

**Suggestion.**
1. Sign in a desktop profile with the second seat.
2. Continue a chat from the first seat there and send a message.
3. Do the same with `/resume` in a terminal profile.
4. Record the results in beta.2.

**Impact.** Confirms the product works, or finds a blocker early.

### S-02 Test on Windows and Linux
**Problem.** These are untested on real machines:
- Windows: process detection (PowerShell CIM), the install path guess, junctions, and
  console output.
- Linux: the community Claude desktop names, and the terminal list.

**Suggestion.** Run WIN-001…006, LNX-001…006 and PROF-012 (start-at-login handover from Tandem) on a real
PC and Linux machine. Ask Beta
users for reports.

**Impact.** Two thirds of the downloads.

### S-03 Restart to see new chats
**Problem.** Claude reads its chat list at startup.

**Suggestion.** After a sync that added chats to a profile, show "N new chats. Restart
this window" with a button. The button quits and reopens that profile gracefully, using
the same code as the sign-in helper.

**Impact.** Sync becomes visible. It reuses `QuitDesktop` and `LaunchDesktop`.

### S-04 Version check
**Problem.** The format guard reacts only when files look wrong.

**Suggestion.** Record the Claude desktop version each sync. Show "Claude was updated
since Tango was last tested" when it is newer than the tested 6.6395.1.

**Impact.** Earlier, clearer warning.

### S-05 Terminal chats in the desktop list
**Problem.** Chats started in a terminal profile have no desktop list entry.

**Suggestion.** Create entries for CLI transcripts. This needs care, because the entry
format would be made up rather than copied.

**Impact.** One chat list everywhere.

### S-06 CLI on PATH
**Problem.** The CLI lives inside the app bundle.

**Suggestion.** A Settings button that adds a `tango` link to a user `bin` folder, plus
an installer option on Windows.

**Impact.** Easier scripting.

### S-07 Tell windows apart
**Problem.** Every desktop window looks like Claude.

**Suggestion.** Show the profile name in the tray item, and optionally set a different
Dock badge per profile (macOS).

**Impact.** Fewer mistakes.

### S-08 Notify on two-seat use
**Problem.** The warning is visible only in the Sync tab.

**Suggestion.** Show a system notification when the warning first appears.

**Impact.** Protects conversations.

### S-09 Signed builds
**Problem.** Unsigned builds need a one-time click-through.

**Suggestion.** Add signing if users ask (Apple Developer and Windows certificate costs).

**Impact.** Smoother installs.

### S-10 Folder watching
**Problem.** Changes wait for the next timer tick.

**Suggestion.** Use file-system notifications, with the timer kept as a backup.

**Impact.** Faster sync.

### S-11 Old app still running
**Problem.** beta.1 had a different app ID, so Tango doesn't notice it. If a user
installs Tango without quitting Tandem, both sync and both show a tray icon.

**Suggestion.** On first start, look for a running `tandem` process and offer to quit
it, with a link to the upgrade steps.

**Impact.** Cleaner upgrades for beta.1 users. Only useful while beta.1 users remain.
